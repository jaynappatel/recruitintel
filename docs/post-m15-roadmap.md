# Post-M15 RecruitIntel roadmap

Status: **PROPOSED — REQUIRES USER APPROVAL**. This is the authoritative candidate sequence after M15 for review; it does **not** authorize M16 or any implementation. It composes the completed M1–M15 architecture at `baae274`.

## Sequence

| Milestone         | Objective                                                     | Product outcome                                                                                           |
| ----------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| M16               | Product beta workflow completion                              | A user can finish the core search-to-outcome lifecycle in the web product.                                |
| M17               | Daily recruiting workflow and reliable in-product alerts      | A user has one actionable, deduplicated daily queue across discovery, deadlines and applications.         |
| M18               | Evidence-backed recruiter intelligence and consented outreach | A user can manage legitimate contacts and reviewed drafts without inferred identities or spam.            |
| M19               | Interview and assessment preparation                          | A user can turn lawful, provenance-bearing interview intelligence into application-linked preparation.    |
| M20               | Private-beta launch readiness                                 | The complete user journey is release-gated for accessibility, performance, operations and support.        |
| M21 (conditional) | Evidence-gated ML production promotion                        | A model may become authoritative only after M14's real-data gates are met; otherwise it remains deferred. |

M16–M20 do not wait for ML readiness. M21 does not block private beta or launch. At this baseline M14 reports `NOT_READY` for personalized ranking, opening forecast, source anomaly, resume outcome and interview-topic tasks; there are zero promoted models.

| Concern                   | Mandatory contract                                                                                                                                                                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| Auth / privacy            | Server-derived actor only; private rows have unambiguous owner scope, export/delete behavior, retention policy and U_A/U_B/unauthenticated/failed-IDOR-no-mutation tests. Admin is not private-data access.   |

| Security / zero cost      | Hostile inputs are validated; diagnostics/logs redact PII, secrets, resume/DOM/message content; `ZERO_COST_MODE=true` keeps the core journey complete with zero paid spend/provider calls.                    |

## M16 — Product beta workflow completion

**Objective.** Turn existing private APIs into an accessible, responsive web workflow from first sign-in through deterministic discovery, resume/match, application tracking, Calendar and privacy controls.

**Why it exists / current gap / user value.** M9–M12 and M10–M11 already implement recommendations, applications, matching, extension grants and private-data controls, but web navigation contains no application, resume, privacy or analytics workflow. This creates the private-beta product without redesigning existing systems.

| Area                           | Scope and acceptance direction                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| In scope                       | Guided first-run setup; preference completion; explicit no-data/degraded states; opportunity search/filter/sort and richer detail; unified saved/dismissed/applied/plan state; resume upload/parse/status/evidence review/correction/delete; exact-match eligibility/citations/UNKNOWN view; application board/detail/timeline/OA/interview/outcome/archive; Calendar deep links; extension install/connect/grant/revoke/status; personal funnel summary; privacy/account controls. |
| Out of scope                   | New identity provider, native mobile app, two-way Calendar, autonomous application, new prediction model, email/push, outreach, new collection provider or a second queue.                                                                                                                                                                                                                                                                                                          |
| Dependencies                   | M6 owner/auth/privacy; M8 lineage; M9 impressions/ranking; M10 ledger/Calendar; M11 secure resume/match; M12 grants/decisions; M15 runtime.                                                                                                                                                                                                                                                                                                                                         |
| Schema / backend               | Prefer composing existing APIs. Add a forward-only migration only for a genuine missing product-state invariant; no synthetic data and no client-supplied owner authority. Add server-owned aggregate/read endpoints only when endpoint composition is insufficient.                                                                                                                                                                                                                |
| Frontend / extension           | Add Resume, Applications and account privacy navigation/routes; improve opportunity/company flow; provide web-issued, scoped extension setup that teaches manual install, expiry/revocation and links decisions back to canonical jobs. Do not expand extension permissions.                                                                                                                                                                                                        |
| Workers / AI / analytics       | Surface existing M7/M11/M12 status. No new worker expected. M13 stays optional and cannot decide eligibility/action. Surface only existing private M14 funnel counts, never prediction or raw analytics.                                                                                                                                                                                                                                                                            |
| Security / privacy / zero cost | Token shown only once and never browser-stored by web; owner API tests, export/delete for new private state, no resume/credential in logs; all core flows work in zero-cost mode.                                                                                                                                                                                                                                                                                                   |
| Concurrency / effects          | Reuse application idempotency, resume version checks, M7 fences and Calendar mappings; UI retries reuse idempotency keys and cannot duplicate a transition, application or Calendar action.                                                                                                                                                                                                                                                                                         |
| Permanent tests                | First run; empty/loading/error/retry; keyboard/mobile/screen-reader; U_A/U_B/unauthenticated/no-mutation; resume/application lifecycle UI; extension expiry/revoke; match UNKNOWN; lineage rendering; privacy; built production lifecycle.                                                                                                                                                                                                                                          |
| Production / preservation      | Preserve M1–M15 APIs/history, Google ciphertext, orphan scan, headers, health/ready, non-root/read-only and zero counters.                                                                                                                                                                                                                                                                                                                                                          |

**Definition of done.** The first four and the sixth/seventh private-beta acceptance cases in `product-beta-gap-analysis.md` pass in a built authenticated runtime. **Do not begin M17 until** M16 owner/IDOR, responsive/accessibility, regression and zero-cost acceptance are green.

## M17 — Daily recruiting workflow and reliable in-product alerts

**Objective.** Unite M9 alerts, M10 due work and M8/M4 signals into a bounded, actionable daily queue and preference-aware in-product workflow.

**Why it exists / current gap / user value.** M9 creates deduplicated in-app alerts, but the product lacks a daily priority view, a consistent event-to-action presentation, recovery states and an optional local-notification policy.

| Area                           | Scope and acceptance direction                                                                                                                                                                                                                                                                                        |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| In scope                       | Daily/weekly now-next-later queue; in-app notification center improvements; evidence-backed opening/deadline/application-follow-up/OA/interview/prep/recruiter actions; preferences; read/dismiss/action tracking; stale/degraded coverage messaging; optional browser-local notifications after explicit permission. |
| Out of scope                   | Mandatory email/SMS/push, paid notification provider, Calendar replacement, opening prediction, automatic actions, background extension crawling.                                                                                                                                                                     |
| Dependencies                   | M9 alert/ranking, M10 lifecycle/calendar, M4 facts, M7 evaluator/fanout, M16 application UI.                                                                                                                                                                                                                          |
| Schema / backend               | Reuse `alerts` unless retention/delivery semantics genuinely need additive rows. Any local/external delivery state needs owner FK, unique dedupe key and bounded retention.                                                                                                                                           |
| Frontend / extension           | Action cards link to canonical opportunity/application/calendar. Extension unchanged unless the user explicitly enables a local notification integration; no new site access.                                                                                                                                         |
| Workers / AI / analytics       | M7 alone evaluates/fans out. No AI required. Instrument actual shown/opened/dismissed/action results without fabricating impressions.                                                                                                                                                                                 |
| Security / privacy / zero cost | Minimal non-sensitive notification text; no resume/credential exposure; owner scope and permission revoke; zero paid dependency.                                                                                                                                                                                      |
| Concurrency / effects          | Transactional materiality/dedupe; delivery attempt before effect; retry cannot duplicate; deletion cancels work and stale workers cannot recreate records.                                                                                                                                                            |
| Permanent tests                | Rule matrix, preferences, dedupe/retry/concurrent fanout, U_A/U_B/no-mutation, retention/delete/fence, permission denial/revoke and production privacy inspection.                                                                                                                                                    |
| Production / preservation      | M9 alert limits and deterministic authority remain unchanged; M15 diagnostics stay aggregate/redacted and zero-cost acceptance remains green.                                                                                                                                                                         |

**Definition of done.** A real signal or due item creates at most one relevant, dismissible owner-scoped in-product notification and follows through to its task. **Do not begin M18 until** notification dedupe, retention, delete races and privacy behavior pass.

## M18 — Evidence-backed recruiter intelligence and consented outreach

**Objective.** Let a user organize public provenance-backed recruiter/contact information and create explicitly reviewed outreach without manufacturing identity, address, employer or relationship claims.

**Why it exists / current gap / user value.** M4 exposes recruiters/evidence and M10 can associate public recruiters to applications; no owner contact, outreach, review, send or follow-up workflow exists.

| Area                           | Scope and acceptance direction                                                                                                                                                                                                                                                                                              |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| In scope                       | Company/job/application contact panel; provenance/reliability/freshness display; user-provided contact methods with source/consent; private association; `DRAFT → REVIEW → APPROVED → SEND_ELIGIBLE → SENT/FAILED`; grounded draft assistance; follow-up/calendar linkage; manual copy/send as the complete zero-cost path. |
| Out of scope                   | LinkedIn scraping/automation, guessed email, AI recipient discovery, autonomous/bulk mail, Gmail ingestion/parsing, mandatory mail provider or relationship claims from weak evidence.                                                                                                                                      |
| Dependencies                   | M4 graph, M6 privacy, M7 safety, M10 application/calendar, M13 grounding and M16 application UI.                                                                                                                                                                                                                            |
| Schema / backend               | Add private owner-scoped contact/outreach data only when needed, with provenance, consent, immutable attempts, status/version/idempotency and retention. Never copy a public recruiter into private truth.                                                                                                                  |
| Frontend / extension           | Contextual contact/outreach views clearly distinguish public evidence, user-provided method and unknown/unverified. Extension unchanged.                                                                                                                                                                                    |
| Workers / AI / analytics       | No worker for manual copy/send. A later approved transport uses M7 prepare-authorize-validate-idempotency-execute-record. M13 cites/abstains and cannot select recipient/send. Capture metadata, not message body.                                                                                                          |
| Security / privacy / zero cost | Private contacts/drafts export/delete; encrypt contact methods if appropriate; redact message/email from diagnostics; validate sources; manual flow is free.                                                                                                                                                                |
| Concurrency / effects          | Approval/revoke/send/delete versioned/locked; send key unique per approved revision and recipient; retry never duplicates; delete/revoke defeats stale worker.                                                                                                                                                              |
| Permanent tests                | Grounding/no-invention/injection, state transitions, owner isolation/no mutation, duplicate approval/send, send-vs-revoke/delete, retry/dead-letter/fence, export/delete/retention and leak/zero-cost tests.                                                                                                                |
| Production / preservation      | Preserve M4 provenance/LinkedIn prohibition, M10 history, M13 guards, M15 runbooks and no mandatory paid sender.                                                                                                                                                                                                            |

**Definition of done.** A user can review cited recruiter evidence, add a consented contact method, explicitly approve a grounded draft and manually send/copy it with a tracked follow-up. **Do not begin M19 until** any configured send path is idempotent, deletable and recoverable.

## M19 — Interview and assessment preparation

**Objective.** Convert legitimate, dated, provenance-bearing interview/OA information into application-linked preparation plans, never claims about what a company will ask.

**Why it exists / current gap / user value.** Company question aggregates, M10 assessments/interviews and Calendar preparation categories exist with no single user workflow.

| Area                           | Scope and acceptance direction                                                                                                                                                                                         |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| In scope                       | Application-context OA/interview prep hub; source-backed topic/question browsing with recency/source count/uncertainty; preparation checklists; explicit edits; Calendar plan/reminders; feedback separate from facts. |
| Out of scope                   | Proprietary/leaked questions, CC-BY-NC/unlicensed data, frequency guarantees, cheating, model-generated interview facts or automatic outcome inference.                                                                |
| Dependencies                   | M1/M2 lawful question intelligence, M10 OA/interview/outcome, M5 Calendar, M7 reminders, M16 app UI and M17 queue.                                                                                                     |
| Schema / backend               | Prefer existing facts/calendar; only owner-scoped plan/feedback metadata with retention and immutable source links. No transcript/raw-answer warehouse.                                                                |
| Frontend / extension           | Preparation hub deep-links from application/alert; transparent evidence/source controls; reuse Calendar. Extension unchanged.                                                                                          |
| Workers / AI / analytics       | M7 creates/reconciles idempotent tasks. M13 may summarize cited permitted evidence and abstains when sparse. M14 records minimized user feedback/outcomes only after action.                                           |
| Security / privacy / zero cost | Notes/feedback private; no protected feature collection; licensing checked before display; deterministic/local core.                                                                                                   |
| Concurrency / effects          | Unique application/template/task keys; Calendar mapping idempotency; task completion/fencing; deletion prevents recreation.                                                                                            |
| Permanent tests                | Provenance/licensing display, sparse/unknown evidence, task dedupe, Calendar retry, owner/IDOR/delete/fence, no raw private analytics/logs and zero-cost.                                                              |
| Production / preservation      | Preserve question observations, M10 ledger and Calendar credential ciphertext; no extension/provider expansion.                                                                                                        |

**Definition of done.** A user with an OA/interview can create an evidence-aware preparation plan, schedule it, and distinguish known topics from uncertainty. **Do not begin M20 until** licensing, privacy, task/calendar idempotency and application-context acceptance pass.

## M21 — Conditional ML production promotion

**Objective.** Permit a narrow model promotion only if M14 makes it safer and more useful than the deterministic baseline.

**Entry criteria.** Candidate `readiness == READY`; real consented labels (never fixtures, AI opinions or fabricated negatives); point-in-time reproducible dataset/hash; chronological holdout; baseline win; calibration/stability/protected-feature review; adequate shadow history; model card; rollback; monitoring. `ZERO_COST_MODE=true` blocks paid/network execution.

**If criteria are unmet.** M21 remains deferred. M9 ranking, M7 anomaly rules, M11 eligibility and M19 evidence frequency remain deterministic and authoritative. A milestone number never creates readiness.
